## What was imported

Everything needed to build a Pando interface without network access:

- `styles.css` and all eight files in `tokens/`
- All 24 React components in `components/`
- `index.js`, written here — the adherence config expects consumers to import
  from a barrel, and the design project does not ship one
- `readme.md` — the brand spec in full
- `_adherence.oxlintrc.json` — the lint rules
- `SKILL.md` — rewritten as a Claude Code skill (the original was written for a
  different skill host and pointed at `README.md`, which does not exist there)

## What was left in the design project

These render as specimen cards in the Design System pane and are reference
rather than build inputs. The prose rules they illustrate are all in
`readme.md`:

- `guidelines/*.html` — 21 specimen cards for color, type, spacing and brand
- `components/**/*.card.html` — seven component specimen pages
- `ui_kits/console/` and `ui_kits/site/` — clickable prototypes of the console
  and the marketing site, built from the spec's wireframes

`Button.prompt.md` and `Button.d.ts` **are** here, kept deliberately as a worked
example of the shape. The absence of the other 23 pairs is intentional, not an
incomplete copy.

## Fetching what is not here

`DesignSync` reads the project. It needs authorization first:

**If `DesignSync` reports it needs design-system access, stop and ask the person
to run `/design-login`.** That is a command they type. You cannot run it, there is
no way around it, and guessing at a component's props instead is worse than
waiting. Say plainly that you need it and why.

Then:

```
DesignSync(method: "get_file",
           projectId: "27583278-89f3-4207-b9af-3fa14d54764a",
           path: "components/core/Card.prompt.md")
```

`method: "list_files"` with the same `projectId` enumerates everything.

### What to fetch, and when

| Path pattern | Fetch it when |
| --- | --- |
| `components/<group>/<Name>.prompt.md` | Before using a component you have not used before. It states when *not* to use it. |
| `components/<group>/<Name>.d.ts` | Phase 8 — pull all 24. The console is TypeScript; without them every component types as `any`, which silently removes the prop checking `_adherence.oxlintrc.json` exists to enforce. |
| `ui_kits/console/*` | Before designing any console screen. Seven files: the apps table, app detail, build log, variables, settings, add-app flow and the dark theme, built from the brand spec's own wireframes. Read it rather than designing those screens from scratch a second time. |
| `ui_kits/site/*` | If building the marketing site, docs or the 404 page. |
| `guidelines/*.html` | Visual reference for color, type, spacing and brand. The prose rules are already in `readme.md`, so this is confirmation rather than instruction. |
| `components/<group>/<group>.card.html` | A rendered specimen of a whole component group. |

`<group>` is one of `brand`, `code`, `core`, `data`, `feedback`, `forms`,
`navigation` — the same layout as `components/` here, so a local file tells you
its remote path.

### Writing back

Don't, casually. The design project is the source of truth and changes belong
there first. The `/design-sync` skill is the supported way to keep a local library
in step — incrementally, one component at a time, never as a wholesale replace.

## Known substitutions, from the source readme

Two things the brand spec describes but did not ship, both flagged upstream:

- **Icons — resolved in phase 8.** Ten Lucide SVGs (ISC) are vendored in
  `assets/icons/`, compiled to a plain JS module by `assets/icons/build.mjs`, and
  `Icon` imports them synchronously instead of fetching from unpkg at runtime.
- **Fonts — resolved in phase 8.** The `.woff2` files are in `assets/fonts/` and
  `tokens/fonts.css` is Google's CSS with local paths. 16 files, 355 KiB, five
  subsets.

  Both were flagged upstream as things to do "for production or offline use", and
  phase 8 is production: a CDN dependency means an installation on a private
  network gets no icons and the wrong type, and Pando is software someone runs on
  their own host.

  **Neither flows upstream.** Same caveat as the logo — these are edits to a copy,
  so `Icon.jsx`, `tokens/fonts.css`, `assets/icons/` and `assets/fonts/` all need
  the same change in the design project, or the next re-sync restores the CDN.
- **The logo** — **resolved 2026-09-12.** Real artwork was supplied and is in
  `assets/logo/`: `pando-wordmark-{light,dark}.{svg,png}`,
  `pando-icon-{ink,paper,night}.{svg,png}` and two favicon PNGs.
  `components/brand/Logo.jsx` is rebuilt from it.

  The official mark turned out to be **different from the spec's description**: "pando."
  with a marker-red full stop, rather than three nested contours with a summit dot. See
  `readme.md` § Assets.

  **This edit does not flow upstream.** The design project is the source of truth and this
  directory is a copy of it, so the same change belongs there — `Logo.jsx`, the new
  `assets/logo/`, and the readme's assets section — or the next re-sync will overwrite the
  real logo with the constructed one.

  C2PA provenance metadata was stripped from the SVGs on the way in: roughly 8 KB per file
  of signing metadata about how each was produced, for artwork whose content is one rect
  and one text element.
